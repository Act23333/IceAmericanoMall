# ADR-045: 数据库结构演进口径变更 —— 废除迁移文件机制，Initialize.sql 为唯一结构真相源

## 背景

仓库此前的数据库演进口径是「双轨」：`database/Initialize.sql` 全量快照（新装库一次到位）+ `database/migrations/` 三段式版本迁移文件（V1.1.0 → V5.8，存量库升级路径）。该口径的前提是**存在带数据的存量库**需要平滑升级。

用户裁决（2026-10-05）：当前数据库**暂无任何存量数据**——所有库均可随时重建，升级路径的前提不成立。为迁移文件维护双份结构定义（快照 + 每个迁移各一份）持续产生同步成本与漂移风险（快照与迁移不一致需人工核对），收益为零。

## 决策（2026-10-05）

1. **删除 `database/migrations/` 目录**（V1.1.0 → V5.8 全部 32 个迁移文件；内容已并入 Initialize.sql 快照，git 历史可追溯）；
2. **`database/Initialize.sql` 成为数据库结构的唯一真相源**——此后一切结构变更（加表/加列/改约束/seed 调整）**直接修改本文件**，不再产生迁移文件；
3. 口径说明：库内无数据 ⇒ 结构变更 = 「删表重建」等价于「ALTER」，无数据保全问题；未来若真实上线产生存量数据，届时再立「结构变更流程」决策（含迁移机制是否恢复）；
4. 各文档中的迁移引用同步清理（AGENTS.md / CLAUDE.md / 02-Architecture / 04-Data-Model / 14-Service-Config-Guide / docker-compose.yml 注释）；历史 ADR（017/019/032/035/036/037 等）中出现的迁移文件路径为**决策当时的存档记录**，不回写——以本 ADR 为现行口径。

## 备选方案

| 方案 | 优点 | 缺点 |
| :--- | :--- | :--- |
| 保留双轨（快照 + 迁移） | 未来有存量库时直接可用 | 无存量数据的前提下纯维护成本；双份结构定义持续漂移风险 |
| 保留迁移但停止新增 | 改动最小 | 旧迁移文件指向的历史结构已并入快照，纯死文件 |
| 引入 Flyway/Liquibase 管理版本 | 工程化 | 同样以存量库为前提；当前无数据，纯属过度建设 |
| **删除迁移、Initialize.sql 唯一真相源（采纳）** | 单一事实源、零同步成本、装库一步到位 | 若未来出现存量数据需重建演进流程（届时另立决策） |

## 后果

**正面**

- 结构定义单一事实源，杜绝「快照与迁移不一致」的漂移面；
- 新装库/重建库一步到位，开发迭代改表零仪式感（改快照 → 重建库）；
- 移除 32 个死文件，数据库目录回到最小形态。

**负面 / 风险**

- **未来产生存量数据后**，结构变更失去平滑升级路径——届时必须重建演进流程（本 ADR 已预告）；
- 历史文档/ADR 中的迁移文件引用成为悬空引用（已在本 ADR 登记为存档口径）；
- `Initialize.sql` 成为高频改动文件（每次结构变更都要动它），需靠评审保证快照质量。
