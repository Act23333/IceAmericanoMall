## 一、产品愿景

**冰美商城 (IcedAmericanoMall)** 是 B2B2C 模式的电商平台，类似淘宝/京东。目标是打造一个集用户购物、商家运营、平台管理于一体的分布式微服务电商系统。

**核心理念**：结合业界主流技术方案与大型互联网公司的工程实践，探索个人全栈开发的最佳路径。不追求空洞的「高可用」「高并发」口号，而是用**技术方案 + 量化结果 + 业务价值**说话。

### 目标特性（量化指标）

| 特性   | 目标                          | 衡量方式                 |
| ---- | --------------------------- | -------------------- |
| 高并发  | 峰值 12000 TPS，P99 延迟 < 500ms | 压力测试报告               |
| 易维护  | 配置变更无需重启，发布频率从周级→日级         | Nacos 配置中心 + 自动化部署   |
| 稳定性  | 电商大促期间零故障                   | 故障记录                 |
| 可扩展性 | 用户量从 10 万→1000 万无需重构        | 架构评审                 |
| 可观测性 | 故障定位从小时级→分钟级                | Prometheus + Grafana |
| 安全性  | 满足等保 2.0 要求                 | 安全审计                 |

## 二、用户角色

| 角色        | 描述                    | 典型行为                       |
| --------- | --------------------- | -------------------------- |
| **游客**    | 未登录用户                 | 浏览商品、搜索、查看商品详情             |
| **普通用户**  | 已注册登录用户               | 下单支付、积分签到、收藏、管理地址          |
| **商家**    | 拥有店铺的用户（一个用户只能成为一个商家） | 管理商品、处理订单、发货、查看数据          |
| **管理员**   | 平台最高权限                | 管理用户/商家/商品/订单、营销配置、数据统计    |
| **第三方系统** | 外部服务                  | 支付网关（微信/支付宝）、短信服务、OSS 对象存储 |

### 登录策略（完整支持，逐步实现）

- 单地登录 / 多地登录 / 多端登录 / 单端登录 / 同端互斥登录
- 七天免登录
- 空闲超时：半小时无操作后需重新登录

## 四、非功能性需求 (NFR)

### 4.1 性能

- 单节点支持 2000+ QPS
- 峰值 12000 TPS，P99 延迟 < 500ms
- 通过 Redis 缓存 + 负载均衡实现

### 4.2 可用性

- 核心交易链路 99.9% 可用
- 非高峰时段自动缩容（未来）

### 4.3 安全性

- 密码 BCrypt 加密存储，禁止明文
- JWT + OAuth2 认证授权
- 人机验证防刷（注册/登录）
- 内部接口（`/internal/**`）与外网接口隔离
- 防越权访问（商家只能操作自己的店铺数据）

### 4.4 可维护性

- Nacos 配置中心实现配置集中管理
- 配置变更无需重启
- 统一异常处理、统一响应格式

### 4.5 可扩展性

- 微服务独立部署、独立扩展
- 数据库预留扩展字段（`expand_json` JSON 列）
- 接口版本化管理

## 五、核心流程 BDD 场景

### 5.1 用户注册

```gherkin
Feature: 用户注册
  作为新用户
  我希望用手机号注册账号
  以便在平台购物

  Scenario: 成功注册
    Given 手机号 "13800138000" 未被注册
    And 验证码 "123456" 在 Redis 中存在且未过期
    And 人机验证通过
    When 用户提交注册请求
    Then 创建用户记录，状态为"正常"
    And 返回 JWT Token 和用户信息
    And 验证码从 Redis 中删除

  Scenario: 重复手机号注册
    Given 手机号 "13800138000" 已被注册
    When 用户提交注册请求
    Then 返回错误 "手机号已注册"

  Scenario: 验证码错误
    Given 手机号 "13800138000" 未被注册
    And 验证码 "123456" 不正确或已过期
    When 用户提交注册请求
    Then 返回错误 "验证码错误或已过期"

  Scenario: 幂等保护
    Given 用户已成功注册
    When 用户使用相同 requestId 重复提交注册
    Then 返回已有注册结果，不重复创建
```

### 5.2 用户登录

```gherkin
Feature: 用户登录
  作为已注册用户
  我希望用手机号和密码登录
  以便访问我的账户

  Scenario: 密码登录成功
    Given 手机号 "13800138000" 已注册，状态正常
    When 用户提交正确的密码
    Then 返回 JWT Token 和 Refresh Token
    And Token 中包含用户角色信息

  Scenario: 密码错误
    Given 手机号 "13800138000" 已注册
    When 用户提交错误的密码
    Then 返回错误 "手机号或密码错误"

  Scenario: 账号被禁用
    Given 手机号 "13800138000" 已注册但状态为"禁用"
    When 用户尝试登录
    Then 返回错误 "账号已被禁用，请联系客服"

  Scenario: 验证码登录（手机号+验证码）
    Given 手机号 "13800138000" 已注册
    And 验证码有效
    When 用户提交验证码登录请求
    Then 直接登录成功，返回 Token
```

### 5.3 下单支付（核心闭环）

```gherkin
Feature: 下单支付
  作为已登录用户
  我希望从购物车下单并支付
  以便购买商品

  Scenario: 成功下单并支付
    Given 用户已登录
    And 购物车中有选中的商品（含 SKU、数量）
    And 用户已选择收货地址
    When 用户提交订单
    Then 创建订单，状态为"待付款"
    And 购物车中已下单商品被清空
    When 用户完成微信支付
    Then 订单状态变更为"待发货"
    And 扣减对应 SKU 库存

  Scenario: 库存不足
    Given 购物车中某 SKU 数量为 5
    And 该 SKU 实际库存为 3
    When 用户提交订单
    Then 返回错误 "库存不足"

  Scenario: 超时未支付
    Given 订单状态为"待付款"
    And 订单创建超过 30 分钟
    When 系统检查超时订单
    Then 订单状态变更为"已取消"
    And 释放被锁定的库存
```

## 六、MVP 范围总结

MVP 要跑通一条完整的用户价值链路：

**用户注册 → 浏览商品 → 加入购物车 → 下单 → 支付 → 商家处理订单 → 用户确认收货**

MVP 目标：一个月内可上线，验证平台模式可行性。
