# ADR-002: 双主键策略 + 金额用分 + 快照模式

## 背景

数据库设计阶段需要确定三个核心约定：主键怎么设计、金额怎么存、订单关联数据怎么保持历史一致。

## 决策

### 1. 双主键策略

每张表同时拥有：

- `id BIGINT AUTO_INCREMENT` — 技术主键，数据库内部关联（外键）使用
- `xxx_id VARCHAR(32)` — 业务唯一标识（UUID），对外 API 暴露使用

**理由**：

- 自增 ID：性能好（BIGINT 索引紧凑），数据库 JOIN 快
- UUID 业务标识：对外不暴露数据规模（安全），语义明确

### 2. 金额统一用分

所有金额字段类型为 `INT`，单位为「分」。

**理由**：

- `FLOAT/DOUBLE` → 浮点精度问题（0.1 + 0.2 ≠ 0.3）
- `DECIMAL(10,2)` → 虽精确但计算需 BigDecimal API，代码冗长
- `INT(分)` → 整数运算快，无精度问题，跨语言一致

### 3. 订单快照模式

下单时将用户地址、商品名称/价格/图片复制到订单表，不引用原表。

**理由**：

- 用户修改地址 → 历史订单地址不变（可追溯）
- 商家修改商品价格 → 已下单价格不变（合同一致性）
- 商家删除商品 → 历史订单仍可查看商品信息

## 后果

- ✅ 数据一致性和历史可追溯性得到保证
- ✅ 对外 API 返回 UUID 不暴露数据规模
- ⚠️ 前端展示金额需自行除以 100 转为元
- ⚠️ 快照导致订单表字段较多（但这是必要的冗余）
