在 MyBatis-Plus（以及其他 ORM）中，**实体类的属性可以使用基本类型，但强烈建议使用包装类型**，尤其是在涉及数据库字段可能为 `NULL` 的情况下。下面从原理和最佳实践两个角度解释。

---

## 一、基本类型 vs. 包装类型的本质区别

| 类型                  | 默认值          | 能否表示 `NULL` | 数据库字段为 `NULL` 时的行为                             |
| ------------------- | ------------ | ----------- | ---------------------------------------------- |
| 基本类型（int、long等）     | 有默认值（如 0、0L） | **不能**      | MyBatis-Plus 会尝试将 `NULL` 映射为默认值（0），可能导致业务逻辑错误。 |
| 包装类型（Integer、Long等） | `null`       | **能**       | 可以准确映射数据库的 `NULL` 值，方便业务判断。                    |

---

## 二、为什么推荐使用包装类型？

### 1. 准确表达业务中的“未定义”状态
- 例如：用户的 `balance`（余额）在数据库中可能为 `NULL`（表示未设置），但业务上余额为 0 和未设置是两种含义。使用 `Integer` 可以区分这两种状态，而 `int` 无法区分。
- 又如：`status` 字段如果使用 `int`，当数据库为 `NULL` 时会被映射为 0，而 0 可能恰好是“正常”状态，导致逻辑错误。

### 2. 避免 SQL 更新时的歧义
- 当使用 `updateById` 时，MyBatis-Plus 默认会更新实体类中所有非 `null` 的字段。如果某个字段是基本类型，其默认值 0 会被当作有效值更新到数据库，可能覆盖原有数据。

### 3. 与数据库字段的 `NULL` 约束对齐
- 数据库字段如果允许为 `NULL`，实体类对应属性就应使用包装类型，否则在映射时会丢失语义。

---

## 三、例外情况：何时可以使用基本类型？

- **主键字段**：如果主键是自增且业务上永远不会为 `NULL`，可以使用 `Long` 或 `long`，但为了统一风格，通常也用包装类型。
- **明确业务上不可能为 `NULL` 的字段**：如 `phone` 字段在数据库中是 `NOT NULL`，且业务上永远有值，可以用 `String`（包装类），但 `String` 本身就是引用类型，不存在基本类型问题。
- **性能敏感场景**（极少）：基本类型在内存占用和访问速度上有微小优势，但除非是海量数据高并发场景，否则差异可以忽略不计。现代 Java 开发中，优先考虑语义正确性。

---

## 四、推荐实践

### ✅ 推荐写法（使用包装类型）
```java
@Data
@TableName("user")
public class UserEntity {
    @TableId(type = IdType.AUTO)
    private Long id;           // 包装类型
    private String userId;
    private String username;
    private String phone;
    private String password;
    private String avatar;
    private LocalDateTime registerTime;
    private Integer status;    // 包装类型
    private Integer balance;   // 包装类型
    private LocalDateTime createTime;
    private LocalDateTime updateTime;
}
```

### ❌ 不推荐（除非有特殊原因）
```java
private long id;       // 基本类型
private int status;    // 基本类型
private int balance;   // 基本类型
```

---

## 五、MyBatis-Plus 的辅助功能

- **自动填充**：对于 `createTime`、`updateTime` 等字段，使用 `@TableField(fill = FieldFill.INSERT)`，即使字段类型是 `LocalDateTime`，MyBatis-Plus 也会自动填充，无需手动处理 `NULL`。
- **逻辑删除**：`@TableLogic` 通常使用 `Integer` 类型，值为 0 表示未删除，1 表示已删除，此时使用包装类型也能准确表达。
- **乐观锁**：`@Version` 字段通常使用 `Integer` 或 `Long`。

---

## 六、总结

- **默认使用包装类型**（`Integer`、`Long`、`Boolean` 等），以准确表达数据库的 `NULL` 值。
- **基本类型只用于业务上绝对不可能为 `NULL` 的场景**，且要确保数据库字段有 `NOT NULL` 约束。
- 在 MyBatis-Plus 中，包装类型是更安全、更符合面向对象设计的选择。

这样设计可以避免因默认值（如 0）导致的业务逻辑错误，也让代码意图更清晰。
