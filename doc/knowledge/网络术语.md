
### 1. Socket（套接字）
- **是什么**：Socket 是操作系统提供的一个编程接口（API），它抽象了传输层（TCP/UDP）的细节，让应用程序可以像读写文件一样进行网络通信。
- **与前后端的关系**：当 Tomcat 或浏览器建立 TCP 连接时，实际上是在操作系统中创建了一个 Socket。应用程序通过这个 Socket 发送和接收数据。**后端不需要知道客户端的网址，只需要通过已建立的 Socket 发送响应**，操作系统内核就会根据 Socket 绑定的 IP 和端口将数据包发回客户端。

---

### 2. UDP（用户数据报协议）
- **是什么**：UDP 也是传输层协议，但它**无连接、不可靠**。它不保证数据包一定能到达，也不保证顺序，但速度快、开销低。
- **与前后端的关系**：前后端分离中，HTTP 请求通常使用 TCP（因为需要可靠传输）。但一些场景会用到 UDP，比如：
  - **DNS 查询**（将域名解析为 IP）。
  - **实时音视频**（如 WebRTC 流媒体，允许丢包但要求低延迟）。
  - **游戏数据同步**（快速更新位置，偶尔丢包可容忍）。

---

### 3. SSH（安全外壳协议）
- **是什么**：SSH 是一种应用层协议，建立在 TCP 之上，用于安全的远程登录和命令执行。它使用加密技术保护会话。
- **与前后端的关系**：虽然 SSH 不直接参与前端页面请求，但它是后端开发、运维部署的常用工具。比如通过 SSH 连接服务器、管理 Docker 容器、配置 Nginx 等。

---

### 4. TLS/SSL（传输层安全性协议）
- **是什么**：TLS（及其前身 SSL）位于传输层和应用层之间，为 TCP 连接提供加密、身份验证和数据完整性保护。**HTTPS 就是 HTTP over TLS**。
- **与前后端的关系**：现在绝大多数生产环境都使用 HTTPS。当浏览器发起 HTTPS 请求时，首先会进行 **TLS 握手**（协商加密算法、交换证书等），然后才通过加密的通道传输 HTTP 数据。后端服务器需要配置 SSL 证书才能支持 TLS。

---

### 5. WebSocket
- **是什么**：WebSocket 是一种应用层协议，它也基于 TCP，但允许客户端和服务器之间建立**持久连接**，实现**全双工通信**（双方可以随时主动发送数据）。
- **与前后端的关系**：在需要实时推送的场景（如聊天、在线协作、股票行情）中，WebSocket 很有用。它和 HTTP 的不同在于：HTTP 是“请求-响应”模式，而 WebSocket 是“长连接+双向推送”。在一些电商项目中，可能会用 WebSocket 实现订单状态实时更新。

---

### 6. IP（互联网协议，网络层）
- **是什么**：IP 负责将数据包从源主机路由到目标主机。它定义了 IP 地址（如 192.168.1.1）和数据包格式。
- **与前后端的关系**：我们说的“客户端 IP”就是 IP 层的概念。负载均衡器可以通过 IP 识别客户端，但真实 IP 可能会被代理隐藏，需要用 `X-Forwarded-For` 传递。

---

### 7. 其他相关概念
- **ARP（地址解析协议）**：在局域网内，将 IP 地址解析为 MAC 地址，用于数据链路层的传输。
- **ICMP（互联网控制报文协议）**：用于网络诊断，如 `ping` 命令就是基于 ICMP。
- **DHCP（动态主机配置协议）**：自动分配 IP 地址给设备，你的电脑连上 Wi-Fi 时就是通过 DHCP 获取 IP。

---

### 总结：它们如何协同工作？

当你在浏览器访问一个 HTTPS 网站时，背后发生了一连串的协议交互：

1. **DNS 查询**（UDP）将域名解析为 IP。
2. 浏览器与服务器建立 **TCP 连接**（三次握手）。
3. 在 TCP 连接之上进行 **TLS 握手**，协商加密参数。
4. 加密后的 **HTTP 请求**（应用层）通过 TCP 连接发送。
5. 服务器（Tomcat 等）通过 **Socket** 读取请求，处理业务，然后将 HTTP 响应写回同一个 Socket。
6. 数据包经过 **IP 路由**，跨越多个网络节点，最终到达你的电脑。
7. 浏览器解密数据，渲染页面。如果需要实时更新，可能会再建立 **WebSocket** 连接。

所有这些协议共同构成了互联网的基石。回到你最初的问题：**后端之所以知道把响应发给谁，是因为操作系统内核维护着每个 Socket 对应的客户端地址（IP+端口）**，这依赖于 TCP/IP 协议栈的可靠交付。上层应用（如 Tomcat）只需要通过 Socket 读写数据，无需操心具体的路由和寻址。




- **三次握手与四次挥手**：属于**传输层（TCP 协议）**的机制。三次握手用于建立可靠的连接，四次挥手用于关闭连接。它们确保客户端和服务器之间能够建立一条稳定的数据传输通道。
    
- **HTTP 请求与响应**：属于**应用层**的协议，建立在 TCP 连接之上。前端发送请求、后端返回数据，都是通过已经建立的 TCP 连接进行数据传输。至于后端是否知道前端来源，这是应用层逻辑，与 TCP 连接本身无关。

socket与websocket区别

|维度|Socket|WebSocket|
|---|---|---|
|**本质**|编程接口（API）|应用层协议|
|**层级**|介于传输层和应用层之间|应用层|
|**与 HTTP 关系**|无关（可承载 HTTP）|基于 HTTP 握手升级而来|
|**连接建立**|需手动通过 TCP/UDP 建立|自动通过 HTTP 握手建立|
|**数据格式**|原始字节流（需自定义协议）|标准帧格式（文本/二进制）|
|**主要应用**|数据库连接、RPC、私有协议|网页实时通信、推送服务|
|**使用难度**|较高（需处理粘包、心跳等）|较低（浏览器原生支持）|

### 一句话总结

- **Socket** 是“运输工具”（卡车），你可以用它来运任何东西（自定义数据）。
    
- **WebSocket** 是“快递服务”（顺丰），它规定了包装盒、运单号和配送流程，专门为浏览器和服务器之间的高效送货而设计。
