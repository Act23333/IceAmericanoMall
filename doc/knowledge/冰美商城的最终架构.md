│
├── 【4. 领域核心层｜必选】domain

│   ├── entity         🔴【高阶DDD可省略】领域实体（业务实体，≠数据库DO）

│   ├── command        🟡【可省略】领域命令

├── 【6. 转换层｜🟡可省略】converter

│
├── 【7. 基础设施实现层｜必选】infra

│   ├── redis         缓存、Lua、分布式限流
│   ├── lock          分布式锁
│   ├── feign         远程调用客户端
│   ├── mq            🟡【可省略】消息队列、事件发送实现
│   ├── third         🟡【可省略】第三方SDK

├── 【12. 公共工具｜🟡可省略】utils

## 三、分层极简释义（分清：必选 / 可省略）

### 🔹 必选（任何微服务都不能删）

1. **controller**：请求入口、参数校验、响应封装
2. **manager**：分布式逻辑收口（锁 / 限流 / 多服务编排）
3. **domain**（基础版）：领域枚举、领域服务核心规则
4. **dto**：三层数据隔离（req/resp/feign）
5. **infra**：中间件底层能力
6. **config / exception / common**：项目基础底座

### 🔹 中小业务 🟡【可直接省略】

1. `application` 应用服务层
2. `domain/event` 领域事件
3. `domain/repository` 仓储接口层（中小直接用 Mapper）
4. `converter` 转换层（简单业务直接 BeanCopy）
5. `infra/mq` 消息队列、事件相关

### 🔹 超大复杂中台 🔴【才需要】

1. 聚合根 aggregate
2. 领域实体 / 值对象
3. 领域规格、复杂领域规则
4. 完整仓储模式

## 六、关键规范（DDD 核心铁律）

1. **领域层 domain 绝对不依赖 基础设施 / DB**
2. 数据库 DO 只允许在 `mapper/infra` 出现，禁止外泄
3. 外部入参、出参、微服务调用 全部用 DTO 隔离
4. 分布式问题（锁 / 限流 / 幂等）统一收口到 **manager**
5. 业务核心规则内聚到 **domain/service**
6. 单向上层依赖下层，禁止反向依赖
