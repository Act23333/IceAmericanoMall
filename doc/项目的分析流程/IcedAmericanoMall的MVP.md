## 一、MVP 的核心目标
MVP 要能够跑通一条完整的用户价值链路：  
**用户注册 → 浏览商品 → 加入购物车 → 下单 → 支付 → 商家处理订单 → 用户确认收货**  
同时，管理员能管理核心数据，商家能处理自己的订单。
---
## 二、MVP 功能清单（按模块）
### 1. 用户端（前台）
- **注册/登录**  
  - 手机号+验证码注册/登录  
  - 账号密码登录（可选）  
  - 人机验证（简单滑块或图形验证码）  
  - 退出登录  
- **个人中心**  
  - 查看/修改基本资料（昵称、头像）  
  - 收货地址管理（增删改查，设置默认）  
  - 我的订单列表（按状态分类）  
- **商品**  
  - 商品分类（一级分类）  
  - 商品列表（按销量、价格排序，简单筛选）  
  - 商品详情（主图、价格、库存、规格选择、购买数量）  
- **购物车**  
  - 添加商品到购物车  
  - 查看购物车（商品列表、数量修改、删除、选中/取消）  
  - 购物车结算跳转  
- **订单**  
  - 订单确认页（选择地址、展示商品、计算总价）  
  - 提交订单（生成订单，状态为“待付款”）  
  - 订单支付（至少一种支付方式，如微信支付）  
  - 支付成功回调，订单状态变“待发货”  
  - 订单详情查看  
  - 取消订单（待付款状态可取消）  
  - 确认收货（待收货状态可确认）  
### 2. 商家端（后台）
- **商家登录**（独立登录入口，可复用用户表但角色为商家）  
- **仪表盘**（简单展示：今日订单数、待发货订单数）  
- **商品管理**  
  - 商品发布（填写标题、图片、价格、库存、描述）  
  - 商品列表（查看、上下架、编辑）  
  - 商品分类（商家选择平台已有分类）  
- **订单管理**  
  - 订单列表（按状态筛选：待付款、待发货、已发货、已完成）  
  - 订单详情（查看买家信息、商品明细）  
  - 发货操作（填写物流单号、选择物流公司）  
- **店铺设置**（店铺名称、logo、联系方式、运费模板简单设置）  
### 3. 平台管理员端（后台）
- **管理员登录**（独立账号体系）  
- **用户管理**（查看用户列表、禁用/启用）  
- **商家管理**（查看商家列表、审核商家入驻申请——简化：后台直接创建商家账号）  
- **商品管理**（查看所有商品、上下架、分类管理——一级分类）  
- **订单管理**（查看所有订单，但不能修改）  
- **基础数据统计**（用户数、订单数、销售额简单折线图）  
### 4. 支付对接
- 集成微信支付（或支付宝）  
- 支付结果回调处理  
### 5. 系统基础
- 统一的登录认证（JWT）  
- 简单的日志记录  
- 统一的异常处理  
- 跨域配置

## 四、为什么这样选？
1. **核心闭环**：包含了从用户注册到商家发货的全部环节，可以验证平台模式是否可行。
2. **开发成本低**：砍掉了营销、客服等复杂模块，一个月内可上线。
3. **数据验证**：基础统计足以判断用户活跃度和订单转化。
4. **易于扩展**：技术架构上预留了接口和数据库字段，后续加功能只需添加模块，不影响核心。

## 六、技术架构建议
- **前端**：H5 使用 Vue3 + Vant UI，后台管理使用 Vue3 + Element Plus，API 统一通过网关。
- **后端**：按之前规划的微服务拆分（用户、商品、订单、支付），但 MVP 可以先合并部分服务（如订单和支付）减少复杂度，但数据库要分离。
- **数据库**：MySQL + Redis（缓存）。
- **部署**：Docker + 单机部署，后续再上 K8s。
